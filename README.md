# RegistryDesk

**RegistryDesk** — локальний desktop-застосунок для перетворення PDF-довідок ЦНАП із Державного реєстру речових прав на нерухоме майно у чистий структурований реєстр співвласників.

Застосунок створений для практичної роботи з довідками по багатоквартирному будинку: імпортувати офіційний PDF, швидко знайти потрібну квартиру або власника та сформувати готовий реєстр для подальшої роботи у XLSX, PDF або CSV.

> Поточна версія: **0.3.0**

## Що вміє RegistryDesk

- імпортувати PDF-довідки ЦНАП щодо багатоквартирного будинку;
- зберігати видобуті дані у локальній SQLite-базі;
- показувати імпортовані реєстри окремими незмінними snapshot-документами;
- будувати чисту таблицю власників із точними частками;
- виконувати живий пошук по таблиці;
- сортувати квартири й приміщення у звичному числовому порядку;
- експортувати вибрані поля у **XLSX**, **PDF** або **CSV**;
- змінювати набір і порядок колонок перед експортом.

RegistryDesk не є редактором реєстру: записи всередині імпортованої довідки не можна додавати, видаляти або виправляти вручну. Якщо документ потрібно обробити повторно, імпортований реєстр видаляється цілком і PDF імпортується заново.

## Основний сценарій роботи

1. На сторінці **«Імпортовані реєстри»** натиснути **«Додати»** та вибрати PDF-довідку.
2. RegistryDesk видобуде дані, збереже їх локально та додасть документ до списку реєстрів.
3. Відкрити реєстр подвійним кліком або кнопкою **«Відкрити»**.
4. Переглядати, шукати й сортувати записи у read-only таблиці.
5. Натиснути **«Експорт»**, вибрати формат, потрібні поля та їхній порядок.

## Інтерфейс

### Імпортовані реєстри

Головна сторінка містить список усіх імпортованих довідок.

Доступні дії:

- **Додати** — імпортувати новий PDF;
- **Відкрити** — перейти до таблиці вибраного реєстру;
- **Експорт** — одразу відкрити діалог експорту;
- **Видалити** — видалити весь імпортований реєстр із локальної БД.

### Таблиця реєстру

Таблиця призначена тільки для перегляду.

Перша колонка **«№»** об'єднує номер і тип об'єкта:

```text
1 кв.
25 кв.
190 кв.
1 прим.
2-2 прим.
```

При сортуванні цієї колонки одночасно враховуються **тип об'єкта** і **номер**: квартири мають вищий пріоритет за нежитлові приміщення, а номери всередині групи сортуються природно — `1, 2, 10, 11, 100`, а не лексикографічно як текст.

Пошук працює по всіх видимих колонках у реальному часі.

### Діалог експорту

Діалог містить два списки:

- **Доступні поля** — усі поля, які можна експортувати;
- **Поля для експорту** — поля, які потраплять у результат.

Кнопки `→` і `←` переносять поля між списками, а `↑` і `↓` змінюють порядок колонок у вихідному файлі.

Підтримуються формати:

- **Excel (.xlsx)**;
- **PDF (.pdf)**;
- **CSV (.csv)**.

## Як зберігаються дані

Усі робочі дані залишаються локально. SQLite-база створюється у:

```text
.data/registrydesk.db
```

RegistryDesk зберігає не лише поля, потрібні для короткої таблиці, а всю інформацію, яку парсер може надійно видобути з довідки, зокрема:

- метадані самої довідки;
- повний витягнутий текст кожної сторінки;
- реєстраційний номер об'єкта;
- тип і адресу об'єкта;
- загальну та житлову площу;
- ідентифікатор ЄДЕССБ, якщо він є;
- записи про речові права;
- вид спільної власності;
- частки;
- дані власників;
- дані юридичних осіб, якщо вони присутні у довідці;
- доступні відомості про попередню реєстрацію.

Оригінальний PDF у SQLite не копіюється.

## Чисте представлення реєстру

У базі зберігаються первинні записи документа. Для перегляду та експорту з них формується чисте представлення.

Наприклад, якщо в довідці для одного власника одного об'єкта є два окремі права по `1/2`, у чистому представленні вони агрегуються у частку `1`.

Частки зберігаються як точні дроби, без використання `float`, тому значення на кшталт `1/3`, `2/3` або `11/20` не втрачають точності.

## Експорт XLSX

Типовий набір колонок:

```text
№ пр. | Загальна площа | № | Власник | Площа у власності | Частка
```

Особливості XLSX:

- квартири та нежитлові приміщення розділяються на окремі секції;
- для кількох співвласників поля рівня об'єкта об'єднуються вертикально;
- дробова частка записується як Excel-формула, наприклад `=1/3` або `=11/20`;
- `Площа у власності` також обчислюється формулою;
- `Загальна площа`, `Площа у власності` та `Частка` мають числовий формат `0.00`;
- наприкінці таблиці виводиться загальна площа всіх об'єктів.

## Експорт PDF

PDF формує готову до перегляду та друку таблицю.

- квартири та нежитлові приміщення мають окремі секції;
- поля рівня об'єкта об'єднуються для співвласників;
- `Загальна площа` та `Площа у власності` відображаються з двома знаками після коми;
- `Частка` виводиться точним дробом так само, як у реєстрі: `1`, `1/3`, `11/20`;
- сторінки автоматично нумеруються.

## Експорт CSV

CSV — плоске представлення: один рядок відповідає одному рядку чистого реєстру.

Файл створюється у **UTF-8 BOM** із роздільником `;`, щоб його було зручно відкривати в Excel з українськими регіональними налаштуваннями.

Оскільки CSV не підтримує формули, значення обчислюються під час експорту. Для дробів використовується компактне десяткове представлення з достатньою точністю, наприклад:

```text
1/2   → 0,5
1/3   → 0,333333333333
3/5   → 0,6
11/12 → 0,916666666667
```

## Встановлення

Потрібен **Python 3.11+**.

### Windows

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -e .
python main.py
```

Також можна запускати через:

```text
run.cmd
```

### Встановлення залежностей окремо

```powershell
pip install -r requirements.txt
```

## Залежності

Основні бібліотеки:

- **PySide6** — desktop GUI;
- **PyMuPDF** — читання PDF;
- **openpyxl** — експорт XLSX;
- **ReportLab** — формування PDF;
- **SQLite** — локальне сховище через стандартний модуль Python `sqlite3`.

## Структура проєкту

```text
src/registrydesk/
├── application/     # сценарії застосунку
├── domain/          # immutable domain-моделі та поля експорту
├── interfaces/      # PySide6 сторінки, моделі таблиць і діалоги
├── repositories/    # робота з SQLite
├── services/        # PDF importer та XLSX/PDF/CSV exporters
├── storage/         # схема БД і міграції
└── utils/           # спільні допоміжні функції
```

Архітектурно GUI не парсить PDF і не працює з SQLite напряму: імпорт, зберігання та експорт розділені на окремі шари.

## Тести

Логіку парсингу, SQLite, сортування та експортерів можна перевірити без запуску GUI:

```powershell
pip install -e ".[dev]"
pytest
```

Для запуску самого інтерфейсу потрібен PySide6.

## Поточні межі

RegistryDesk орієнтований на PDF-довідки ЦНАП щодо багатоквартирного будинку у структурі, яку підтримує поточний парсер. Якщо формат державної довідки зміниться, parser потрібно буде адаптувати під нову структуру документа.
